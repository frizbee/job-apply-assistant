# Indeed: страница входа не должна прерываться новыми поисковыми переходами

## Причина

Ранее `goto(..., "Indeed")` ожидал только исчезновение признаков CAPTCHA через общий `page_ready()`. Страница входа без такого признака могла считаться готовой. Поиск получал пустой список `[data-jk]` и открывал следующий keyword, прерывая ручной ввод. Короткий пустой документ между редиректами также мог ошибочно пройти проверку «не CAPTCHA».

В application-flow отдельно распознавались только пути `secure.indeed.com/(auth|account)`, без полной поддержки других login/account URL и форм входа на исходном URL.

## Изменения

- Добавлено Indeed-specific ожидание `indeed_wait_ready()` для переходов к поиску/detail и для application-flow.
- Распознаются auth/account/login пути, account/auth-поддомены, видимые password/username-поля и заголовки входа. Внешняя OAuth-страница не считается готовой Indeed-формой.
- Требуется положительное свидетельство нужной стадии: карточки или явный no-results блок для поиска, detail-контейнер для вакансии, application controls для формы. Отсутствия CAPTCHA недостаточно.
- После появления готовой страницы проверяется стабильный URL/состояние не менее секунды. Промежуточный blank/redirect документ сбрасывает ожидание.
- Ожидание пассивное, до 10 минут, с поддержкой Stop. В helper нет `goto()`/`reload()`. Если вход/проверка не завершены, текущий source останавливается, а не открывает следующий keyword. Логин/OTP/пароль приложение не заполняет.
- Другие площадки остаются на прежней ветке общего navigation helper; их адаптеры не менялись. Submit guards, история и пользовательские настройки не ослаблялись/не сбрасывались.

## Проверка

**498 тестов прошли**, включая 8 новых unit/локальных Chrome-проверок: сохранение введённого email при нескольких проверках, один app-goto без reload, отсутствие перехода к следующему keyword во время входа, blank redirect, auth overlay поверх результатов, timeout и отсутствие заполнения application до входа. Изолированная navigation-регрессия использует уже готовую форму; проверка входа покрывается отдельными тестами.

```bash
AUTOAPPLY_BROWSER_TESTS=1 .venv/bin/python -m unittest discover -s tests
```

В реальном Chrome Indeed вернул HTTP 403, title `Just a moment...`, `Additional Verification Required`. В диагностике после исправления: 12 секунд пассивных проверок, **app-goto=1, app-reload=0**, шесть `ready=false`, следующий keyword не открыт. Три события навигации main frame происходили на стороне сайта, не от дополнительных вызовов навигации приложения. Успешный реальный вход/заполнение не подтверждены, отклики не отправлялись. SHA-256 основных history/settings/CSV/log файлов не изменились.

Локальные диагностические результаты: `data/browser-diagnostics/indeed-auth-review/before-fix.json`, `after-fix.json` (Git ignored).

## Оставшееся ограничение

Код не может гарантировать отсутствие собственных обновлений Indeed/Cloudflare и не обходит проверки. Если после перезапуска приложения страница продолжает обновляться, нужно отличать сайт-инициированные переходы от app-goto; автоматическое повторение поиска или смена fingerprint/proxy ради обхода проверки не добавлялись. Для применения исправления необходимо перезапустить GUI и начать новый тест.

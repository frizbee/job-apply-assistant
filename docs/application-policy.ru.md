# Поиск и подача по AGENTS.md

## Что включено

В `config.yaml` включён `application_policy.enabled: true`. При старте CLI,
GUI или `tools/linkedin_assisted.py` политика заменяет старые сохранённые
ограничения поиска:

- источник LinkedIn, все девять утверждённых запросов;
- `CV_Andre2026.pdf` **из корня**, проверка хеша и соответствия проверенному профилю;
- утверждённый cover letter из `AGENTS.md`;
- глобальные/региональные и страновые запросы для Америки, Европы, Африки и
  Океании; неоднозначные трансграничные страны также ищутся, но требуют уточнения;
- Индия/страны Азии не становятся подходящими только потому, что попались
  в Worldwide. География каждого результата проверяется отдельно. Global,
  включающий Аргентину, не исключается из-за возможности найма также в Азии;
- без отсечения по возрасту публикации и без старого лимита в две страницы;
- отсутствие Easy Apply не снижает оценку и не исключает вакансию;
- Remote, активность, география и обязательные ограничения проверяются отдельно
  от оценки опыта. Текст JD о юридических ограничениях не заменяется догадками.

Списки названий в LinkedIn зависят от сайта. Неподдерживаемый регион/сбой поиска
сохраняется как `blocked`, а не «в регионе нет вакансий». Не гарантируется доступ
ко всем вакансиям мира: есть ограничения выдачи LinkedIn, входа, пагинации и
времени запуска. Незавершённые страницы сохраняются для продолжения. После
завершения полного круга новый круг запускается командой `new-scan` ниже.

## Оценка JD — не процент слов

Старый `technical-coverage-v1` больше не используется для принятия решений.
`jd-evidence-v2` разбирает полный доступный JD и CV. Для каждого требования
сохраняются исходная выдержка из JD, выдержка из CV либо отсутствие подтверждения,
классификация и объяснение. Проверяется наличие цитат именно в текущих документах.

Процент рассчитывает Python, а не модель:

```text
100 × Σ(вес × подтверждение) / Σ(вес)

Обязательное требование: вес 3
Основная обязанность:    вес 2
Nice-to-have:            вес 0 (не снижает оценку)

Подтверждено CV:         1
Частично подтверждено:   0.5
Не подтверждено:         0
```

Допустимые альтернативы — один критерий, не перечень независимых штрафов.
Оценка **≥70%** означает добавление в очередь подходящих. Юридические,
географические, языковые и иные явные обязательные ограничения сохраняются
отдельными блокерами: высокий процент не даёт права их игнорировать.

Автоматическая оценка использует существующий адаптер **только бесплатных
OpenRouter-моделей**. При оценке на этот сервис передаются **CV и полный JD**.
Платные модели не вызываются. При отсутствии ключа, неподдерживаемом провайдере,
ошибке, обрезанном ответе или недостоверных цитатах вакансия остаётся
`needs_assessment`. Это не отказ кандидату и не переход к старому подсчёту слов.
Профиль/ключ берутся из существующей настройки LLM. Ручной разбор не требует API.

Это объяснимая, но **не объективная гарантия соответствия и не вероятность найма**:
модель может неверно интерпретировать требования или пропустить их. Проверка
цитат подтверждает происхождение текста, но не доказывает правильность вывода.
Для важных заявок проверять критерии и блокеры вручную. Наличие фразы в CV само
по себе не подтверждает любую интерпретацию уровня опыта.

## Очередь, отправки и возобновление

`data/candidates.json` — постоянная приватная очередь с полным JD, хешем CV,
оценкой, критериями, блокерами, ссылками, способом подачи, событиями и прогрессом
поиска. Файл создаётся атомарно с правами `0600`. Повреждённая очередь не затирается.

`data/applied.json` и `data/applications.csv` остаются главным журналом отправок.
История не очищается и не сбрасывается. `submission_pending` сохраняется до
клика; отправка считается подтверждённой только после нового подтверждения сайта.
Pending, неясные исходы, сообщения пользователя о внешней отправке защищены
от автоматического повтора, в том числе при изменении политики поиска.

При заполнении неизвестных полей заявка остаётся в очереди. Результат пропуска
разделяет Remote/географию/неактивность/оценку/ошибки/ожидание пользователя.
Лимит отправок не превращает подходящую вакансию в неподходящую: она сохраняется
для следующего запуска. Ограничения частоты, длительности и доверенных сайтов
сохраняются. Не запускать два процесса с одним каталогом данных одновременно:
очередь и история рассчитаны на одного писателя, не на распределённую блокировку.

Просмотр очереди:

```bash
.venv/bin/python tools/review_candidates.py list
```

Ручная оценка — JSON с полным набором критериев и исходными цитатами:

```json
{
  "complete": true,
  "criteria": [
    {
      "requirement": "Название требования из конкретного JD",
      "importance": "mandatory",
      "jd_quote": "ТОЧНАЯ выдержка из сохранённого JD",
      "verdict": "meets",
      "cv_quote": "ТОЧНАЯ выдержка из корневого CV",
      "explanation": "Почему этот опыт подтверждает именно это требование"
    }
  ],
  "blockers": []
}
```

Это только схема, **не готовая оценка**. Перечислить все существенные требования,
а не только совпавшие. Для `partial` нужна цитата CV; для `not_evidenced` поле
`cv_quote` может быть пустым. Блокер содержит `kind`, `jd_quote`, `verdict`
(`unknown`/`unmet`), `explanation`. Юридические сведения не додумывать.

```bash
.venv/bin/python tools/review_candidates.py assess JOB_ID review.json
.venv/bin/python tools/review_candidates.py new-scan
```

`assess` проверяет цитаты, хеш CV, пересчитывает процент и блокеры. Отправку он
не разрешает и не запускает. `new-scan` сбрасывает **только поисковые курсоры**,
сохраняя кандидатов и всю историю отправок; не выполнять параллельно активному
поиску/GUI. Во время одного процесса очередь не является межпроцессным lock.

## Браузер и «готово»

GUI: `./run.sh`. Плашка политики показывает, что старые поля поиска переопределены.
Кандидаты доступны также через защищённый токеном `/api/candidates`.

Для управляемой из чата сессии:

```bash
.venv/bin/python tools/linkedin_assisted.py
```

Она сохраняет браузер открытым и **не отправляет форму автоматически** при поиске.
Локальный контроллер слушает только `127.0.0.1`; порт и приватный Bearer-токен
записываются в игнорируемый `data/browser-diagnostics/assisted-session.json`.
Все запросы — POST с токеном; не публиковать токен или заполненные формы.

- `/search`: продолжить сбор до следующей формы/границы порции работы. Порция по
  времени не является пределом просмотренных вакансий: ответ `continue_search`
  означает, что нужно продолжить, а не что поиск завершён.
- `/queue`: получить сохранённую очередь и прогресс.
- `/assessment`: `job_id` и `review` — сохранить ручную доказательную оценку.
- `/open`: `job_id` подходящего кандидата; JD и ограничения проверяются заново.
- `/ready`: `job_id`, текущий `step`, `consent: true` — только после сообщения
  пользователя «готово» для этой заявки. Проверяет текущий документ и CV,
  обязательные поля и действие. Next не объявляется отправкой.
- `/skip`: `job_id`, `step` — отложить без потери подходящей вакансии.

Внешняя ссылка открывается в браузере даже при отсутствии Easy Apply.
Поддерживаемый HTTPS ATS допускает проверенную отправку после «готово» только
при подтверждённой идентичности должности/компании и неизменном документе.
Редиректы, смена вакансии и недоверенные form action не становятся безопасными
из-за нажатия «готово».

Для неизвестного/неподтверждённого сайта автоматический Submit запрещён. Агент
просит пользователя отправить вручную. **Только после отдельного согласия на
ручную отправку** `/manual-send` с `job_id`, `step`, `consent: true` записывает
pending и разрешает один ручной финальный клик. После явного сообщения пользователя
об отправке `/reported-sent` с `job_id`, `reported_sent: true` сохраняет
`submission_unconfirmed` и пометку «сообщено пользователем», не подтверждённый успех.
До разрешения отправки защитный обработчик может блокировать submit-контролы,
включая вход на неизвестный сайт: в таком случае не обходить ограничения
автоматически, а попросить пользователя пройти вход отдельно и заново проверить
страницу заявки. Не снимать проверку доверия ради автоматического заполнения.

Test mode берётся из сохранённых настроек; контроллер больше не включает LIVE
принудительно. В Test mode ни `/ready`, ни ручное разрешение не отправляют заявку.
Изменения кода не обновляют уже запущенный старый процесс: после завершения/
сохранения текущей формы перезапустить его. Само редактирование кода не запускает
поиск, передачу CV модели или отправку заявок.

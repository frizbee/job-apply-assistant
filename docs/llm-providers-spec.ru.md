# Спецификация: несколько LLM-провайдеров и выбор моделей

Статус: **основные решения согласованы; конфигурация и credentials реализованы**, native/платные адаптеры и UI/CLI-селекторы ещё не выполнены.
Дата: 2026-10-21.

### Согласованные решения

- Ключи хранятся в локальном plaintext `.env`; системное хранилище секретов не входит в первую версию.
- `.env` и локальные варианты `.env.*` исключены из Git. `.env.example` — явное исключение: пустой шаблон для хранения в репозитории, без действующих ключей.
- Выбор — через именованные профили моделей в GUI и CLI. Профиль объединяет провайдера, точный ID модели, правила стоимости и лимиты; последний выбранный профиль сохраняется без ключа и без будущего согласия на расходы.
- Наличие ключа в `.env` не выбирает провайдера автоматически и не включает оплату.
- Выходной лимит V1 — 4096 токенов по умолчанию и не более 4096; меньшие совместимые значения допустимы. На одно подтверждённое платное действие — один генерационный запрос, без автоматических повторов.
- Платный анализ требует отдельного согласия перед каждым запросом; согласие не сохраняется для последующих анализов.
- Транспорт V1 — stdlib `urllib`, без новых SDK OpenAI/Anthropic.
- Выбор моделей предусмотрен для обоих native-провайдеров. Точные ID и возможности проверить при реализации по актуальным каталогам; одобрение механизма не означает выбора конкретной модели или разрешения платного smoke-test.

Реализованный этап foundation:

- `llm_config.py`: профили, строгая валидация, приоритеты, immutable snapshot и его идентификатор. Отсутствующий legacy-раздел даёт только безопасный free-профиль; явный невалидный раздел отклоняется. YAML-дубликаты не перезаписываются молча.
- `llm_credentials.py`: раздельная загрузка ключей, безопасные метаданные, UTF-8, атомарное сохранение/удаление, изоляция провайдеров и внутрипроцессная блокировка записи. Environment не изменяется; временные `.env.*` также исключены из Git. На POSIX новый/заменённый файл имеет права `0600`.
- `config.yaml`: free-профиль по умолчанию и незавершённые placeholders `openai`/`claude`. Присутствие/формат ID означает только структурную готовность, не проверенную доступность или capabilities модели.
- `apply.py`/`gui.py`: resolver и совместимые wrappers ключей, проверка настроек при загрузке/сохранении, безопасные сведения в state. Не реализованный native/explicit-адаптер отклоняет анализ до сети без переключения на OpenRouter. Старый бесплатный адаптер получает лимит вывода и HTTP-тайм-аут из выбранного free-профиля.
- Сохранённые настройки используют `llm_preferences: {profile, overrides: {profile_name: {model?, max_output_tokens?, timeout_seconds?}}}`. Overrides относятся только к своему профилю; нельзя сохранить provider, ключ или согласие на расходы через этот объект. Python-resolver принимает overrides текущего вызова; передача выбора из GUI/CLI будет подключена на последующих этапах.
- 40 новых unit-тестов; полный локальный результат: **407 тестов прошли — 297 unit и 110 браузерных**. Реальные LLM-запросы и отклики не выполнялись.

Добавленные конфигурация, ключи, шаблон и Git-правила не означают, что адаптеры OpenAI/Anthropic уже реализованы. Негенерационная проверка native credentials, сетевые ограничения нового транспорта и GUI opt-in для сохранения ключей остаются следующими этапами; прежний GUI-сценарий OpenRouter пока сохраняет проверенный введённый ключ как раньше.

## 1. Цель и границы

Добавить выбор провайдера и модели для анализа CV, сохранив существующий бесплатный OpenRouter-режим и все проверки безопасности.

Поддерживаемые подключения:

1. OpenRouter: автоматический выбор бесплатной модели или явно выбранная модель.
2. OpenAI API напрямую.
3. Anthropic / Claude API напрямую.

Пользователь может настроить несколько именованных LLM-профилей, но для одного анализа выбирается **ровно один профиль**. «Несколько моделей» не означает параллельную отправку резюме нескольким компаниям.

### Входит в первую версию

- Анализ извлечённого текста CV и возврат профиля по существующей схеме.
- Выбор через GUI, конфигурацию и CLI.
- Раздельные ключи, явное разрешение платного обращения, ограничения запросов.
- Метаданные результата, расход токенов при наличии, тестирование без реальных платных запросов.

### Не входит

- Генерация ответов на каждую анкету, автоматический ответ на неизвестные/юридические вопросы.
- Управление браузером через LLM, выбор вакансий агентом, изменение правил Submit или лимитов откликов.
- Отправка PDF/DOCX провайдеру, OCR, инструменты модели, web search и другие оплачиваемые дополнения. Передаётся только локально извлечённый текст.
- Одновременный анализ несколькими моделями, автоматическое сравнение результатов, локальные LLM.
- Произвольный OpenAI-compatible endpoint, Azure, Bedrock, Vertex, OAuth и использование подписки ChatGPT/Claude вместо API-ключа.
- Жёсткий денежный бюджет: лимит токенов и предупреждение о стоимости не гарантируют верхнюю границу счёта в долларах.

## 2. Текущее состояние

- `cv_profile.py`: извлечение текста, схема, JSON-парсинг, локальная валидация; OpenRouter-транспорт и выбор только моделей `:free`.
- `gui.py`: один OpenRouter-ключ, проверка через `/key`, кнопка анализа; тексты обещают исключительно бесплатную работу.
- `apply.py`: чтение/сохранение `OPENROUTER_API_KEY`, терминальный сценарий анализа и подтверждения профиля.
- Кэш профиля связан с SHA-256 содержимого CV. Start проверяет идентичность CV, worker повторяет проверку перед запуском.
- `requirements.txt`: SDK OpenAI/Anthropic пока отсутствуют. `urllib` уже используется для HTTPS.

Просто снять фильтр `:free` недостаточно: различаются авторизация, форматы запросов/ответов, поддерживаемая JSON Schema и правила обработки расходов.

## 3. Обязательные инварианты

1. Обновление приложения не включает платные запросы для существующих пользователей.
2. Бесплатный режим не вызывает генерацию, пока бесплатность модели не подтверждена актуальными метаданными. Неполные/невалидные данные о цене не считаются нулевой ценой.
3. Нет автоматического перехода между провайдерами или с бесплатной модели на платную.
4. Выбор `paid_allowed` сам по себе **не является согласием на запрос**. Для каждого платного анализа нужно отдельное подтверждение выбранных провайдера и модели.
5. Ключ передаётся только своему провайдеру и никогда не включается в пользовательские настройки, API-ответы GUI, логи, снимки состояния тестов или сообщения об ошибках.
6. Результат проходит существующие строгий JSON-парсер и полную локальную валидацию. Structured Outputs не заменяют проверку достоверности фактов пользователем.
7. Обрыв, отказ модели, неполный ответ, неизвестный формат или несоответствие схеме не дают частично заполненный доверенный профиль.
8. Перед публикацией результата проверяется, что содержимое CV не изменилось за время анализа.
9. Провайдер, модель, согласие и ограничения фиксируются в неизменяемом снимке одного анализа. Другой запрос GUI не может изменить его настройки во время работы.
10. Ошибка нового анализа не подменяет результатом другого провайдера ранее проверенный профиль.

## 4. Модель конфигурации

### 4.1. Именованные профили

Добавить раздел `llm` в `config.yaml`. Пример структуры:

```yaml
llm:
  default_profile: free
  profiles:
    free:
      provider: openrouter
      selection: free_auto
      model: null
      cost_policy: free_only
      max_output_tokens: 4096
      timeout_seconds: 180
    openai:
      provider: openai
      selection: explicit
      model: null
      cost_policy: paid_allowed
      max_output_tokens: 4096
      timeout_seconds: 180
    claude:
      provider: anthropic
      selection: explicit
      model: null
      cost_policy: paid_allowed
      max_output_tokens: 4096
      timeout_seconds: 180
```

`model: null` у explicit-профиля — незавершённая настройка, а не разрешение выбрать модель автоматически. Такой профиль можно показывать в GUI, но нельзя использовать до выбора поддерживаемого ID модели. Конкретные production ID выбрать и проверить при реализации по актуальному каталогу провайдера; примеры документации не должны навсегда фиксировать «последнюю» модель.

Пользователь может добавить несколько профилей одного провайдера, например `openai-fast` и `openai-quality`, с разными явно указанными моделями.

### 4.2. Поля и ограничения

| Поле | Правило |
|---|---|
| Имя профиля | Непустой ограниченный идентификатор; уникален |
| `provider` | Только `openrouter`, `openai`, `anthropic` |
| `selection` | `free_auto` только для OpenRouter; иначе `explicit` |
| `model` | Точный ограниченный ID; обязателен при запуске explicit-профиля |
| `cost_policy` | `free_only` или `paid_allowed`; native API в V1 считать потенциально платными |
| `max_output_tokens` | Целое 256–4096, по умолчанию 4096; дополнительно не выше допустимого для выбранной модели |
| `timeout_seconds` | Целое 10–180; HTTP-тайм-аут, не обещание отмены обработки на сервере |

Неизвестные поля, bool вместо целого, неизвестный профиль и противоречащие комбинации отклоняются. Не заменять ошибочную настройку молча на другой провайдер или дефолтную модель.

Объём входного CV в V1 сохраняет текущий предел 60 000 символов. Если текст сокращён, GUI/CLI предупреждает пользователя; факт сокращения входит в метаданные результата. Это ограничение символов, не точный подсчёт входных токенов. При превышении контекстного окна модели анализ завершается понятной ошибкой без автоматического увеличения лимитов.

### 4.3. Приоритеты

От низшего к высшему:

1. Встроенный безопасный дефолт: `free` / OpenRouter `free_auto`.
2. Раздел `llm` в выбранном приложением `config.yaml`.
3. Сохранённые пользовательские предпочтения `user_settings.json`: выбранный профиль и проверенные overrides его модели/лимитов.
4. Явный выбор текущего обращения GUI **или** аргументы текущего запуска CLI.

CLI и GUI — отдельные пути запуска; их overrides не смешиваются задним числом. В V1 переменные окружения задают ключи, но не скрыто переопределяют провайдера, модель или разрешение расходов.

Результат разрешения настроек — один `ResolvedLLMConfig`, повторно проверенный до сети. Сохранённый выбор не содержит ключей, HTTP-заголовков, согласия на будущие расходы или произвольного base URL.

## 5. Выбор и обнаружение моделей

- В GUI сначала выбирается профиль, затем поддерживаемая модель внутри его провайдера. Явный ID можно ввести вручную, но он проходит ту же проверку доступности/совместимости.
- Не смешивать модели OpenRouter с native ID OpenAI/Anthropic: это разные пространства имён.
- Список доступных моделей не означает поддержку Structured Outputs или всех параметров запроса.
- Адаптер хранит проверяемое описание возможностей поддерживаемых семейств/ID: формат схемы, лимит вывода, допустимость параметров. Неподдерживаемая модель завершается `unsupported_model`, без генерационного «пробника» и переключения на более дорогую модель.
- Метаданные можно кэшировать в памяти с TTL 5 минут; бесплатность OpenRouter повторно проверяется для каждого выбранного кандидата непосредственно перед генерацией, без использования устаревшего подтверждения цены.
- Для `free_auto` сохраняется текущий предпочтительный порядок и fallback между не более чем четырьмя **повторно проверенными бесплатными** моделями. Отсутствующее поле цены, отрицательная/нечисловая/неограниченная цена или недоступный каталог не разрешают вызов.
- Для `explicit` V1 не использует fallback. Ошибка выбранной модели показывается пользователю.
- Если OpenRouter explicit-модель имеет подтверждённую нулевую стоимость, `free_only` допустим. Иначе нужны `paid_allowed` и согласие на текущий запрос. Неизвестная стоимость отображается как неизвестная, а не «бесплатно».

## 6. Ключи и сетевые границы

### 6.1. Раздельные credentials

| Провайдер | Переменная |
|---|---|
| OpenRouter | `OPENROUTER_API_KEY` |
| OpenAI | `OPENAI_API_KEY` |
| Anthropic | `ANTHROPIC_API_KEY` |

Приоритет: environment → соответствующая запись в локальном `.env`. Непустой явно введённый в GUI ключ используется для выбранного провайдера; сохраняется только по отдельному выбору «сохранить ключ». Пустой ввод означает «использовать сохранённый», а не удалить его. Сохранение выполнять после успешной проверки авторизации; отсутствие сетевого подтверждения не считать валидным ключом.

Отдельное действие «забыть сохранённый ключ» удаляет только запись выбранного провайдера из `.env` и не может удалить environment-переменную родительского процесса. Интерфейс объясняет источник действующего ключа без отображения самого значения.

- Убрать универсальное требование префикса `sk-or-`; проверять непустоту, ограниченную длину и недопустимые управляющие символы. Форма ключа не доказывает его действительность.
- Проверку ключа выполнять через доступный негенерационный endpoint провайдера. У native API не предполагать существование OpenRouter `/key`.
- Успешный запрос списка моделей не доказывает наличие средств или доступа к генерации конкретной модели.
- `/api/state` возвращает только `has_key`/источник для каждого провайдера, не значение или фрагмент ключа.
- `.env` остаётся plaintext-хранилищем: это явно сообщается пользователю. Не называть его шифрованным хранилищем. Использовать UTF-8, атомарную замену и ограниченные права доступа там, где ОС это поддерживает; не портить остальные записи. Keychain/Credential Manager — отдельное будущее улучшение.
- Путь хранилища — `HOME/.env` приложения: при запуске из исходников это корень проекта, для packaged-приложения — каталог пользовательских данных. Корневой `.env.example` содержит только пустые `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` и пояснения. В Git и release-артефакты нельзя включать пользовательский `.env`; безопасный шаблон допускается.

### 6.2. HTTP

Фиксированные API-hosts: `openrouter.ai`, `api.openai.com`, `api.anthropic.com`. Использовать TLS с проверкой сертификата; не разрешать пользовательский `base_url` в V1.

Редиректы с авторизацией не выполнять автоматически: отклонять 3xx, а не передавать ключ другому host. Ключ одного провайдера никогда не отправляется в каталог или API другого. Провайдерные ответы об ошибках не пересылать в GUI/лог целиком: они могут содержать входной текст, персональные данные или внутренние HTTP-детали.

## 7. Архитектура

Предлагаемое разделение:

```text
cv_profile.py         извлечение текста, SCHEMA, parse_json(), validate(), orchestration
llm_config.py         схема настроек, профили, разрешение приоритетов, snapshot
llm_credentials.py    раздельные ключи и атомарная работа с .env
llm_providers.py      адаптеры/транспорт, capabilities, нормализованные ошибки и ответы
gui.py               выбор, показ расходов/ошибок, явное согласие пользователя
apply.py             CLI, сохранение предпочтений, подтверждение результата
```

При росте адаптеров `llm_providers.py` можно разделить на пакет; не менять остальной бот ради структуры каталогов.

### 7.1. Общий контракт

```text
Provider.list_models(credentials) -> list[ModelInfo]
Provider.check_credentials(credentials) -> CredentialStatus
Provider.extract_profile(prompt, schema, config, credentials) -> GenerationResult

GenerationResult:
  json_text
  provider
  model_requested
  model_returned?
  finish_status
  usage? {input_tokens, output_tokens, другие доступные счётчики}
  request_id?
```

`ModelInfo` различает доступность, известную совместимость и цену/неизвестную цену. `GenerationResult` не содержит ключей и не делает сырой ответ провайдера частью пользовательских логов.

Оркестратор принимает результат только при допустимом завершении, затем вызывает общий `parse_json()` и `validate()`. Нельзя брать первый попавшийся текст из reasoning/tool/refusal-блоков и считать его профилем.

### 7.2. OpenAI

- Native Responses API: `POST https://api.openai.com/v1/responses`.
- Авторизация Bearer; запрос со Structured Outputs через `text.format`.
- Явный лимит выходных токенов; `store: false` для ответа. Это не обещание полного отсутствия хранения данных у провайдера.
- Не отправлять `temperature` и прочие необязательные параметры без подтверждённой поддержки выбранной моделью.
- Проверять completed/incomplete/refusal и документированную структуру output; извлекать именно итоговый JSON-текст.

### 7.3. Anthropic

- Native Messages API: `POST https://api.anthropic.com/v1/messages`.
- `x-api-key`, явный `anthropic-version`, `max_tokens`.
- Structured Outputs через `output_config.format` для поддерживаемых моделей.
- Проверять `stop_reason`, refusal/обрезку и типы content-блоков; не использовать tool use в V1.

### 7.4. OpenRouter

- Сохранить Chat Completions и обработку structured/non-structured бесплатных моделей.
- Для explicit-профиля использовать только выбранный ID, без провайдерного fallback приложения. Сетевую маршрутизацию самого OpenRouter описывать отдельно от переключения моделей приложения.
- Повторно проверять ограничения выбранного cost policy перед генерацией.

### 7.5. JSON Schema

Полная существующая `SCHEMA` остаётся источником локальной проверки. Для транспорта строится отдельная копия под возможности провайдера.

Если API не поддерживает `minimum`, `maximum`, длины, `pattern` или ограничения массивов, адаптер передаёт допустимую схему и переносит описание ограничений в prompt/description. **Локальный оригинал не ослабляется и не мутируется.** Отклонённый провайдером формат не должен запускать автоматический платный повтор с другой схемой.

### 7.6. Зависимости

Для V1 согласован существующий stdlib HTTPS-транспорт `urllib`, без новых SDK. Нужные API-контракты покрываются транспортными тестами. Возможный переход на SDK вынести в отдельное будущее изменение с согласованием, фиксацией версий, проверкой retries/redirects и упаковки Windows/macOS. Не допускать скрытых повторных платных запросов.

## 8. GUI и локальный API

### 8.1. Сценарий пользователя

1. Загрузить CV.
2. Выбрать LLM-профиль и модель.
3. Указать ключ выбранного провайдера или использовать ранее настроенный.
4. Увидеть, куда передаётся текст CV, бесплатный ли режим и какие ограничения действуют.
5. Для платного/потенциально платного режима подтвердить отдельный checkbox текущего запроса.
6. Запустить анализ; проверить полученные данные. Сам выбор провайдера не выполняет генерацию.

Платное согласие не сохраняется в настройках и сбрасывается после анализа, изменения профиля/модели/лимита токенов или замены CV. Запрос с устаревшим идентификатором настроек/CV отклоняется до передачи текста провайдеру.

На время анализа блокируются изменение активного выбора, повторный анализ, загрузка CV и Start — как в UI, так и серверной блокировкой. Stop означает запрос отмены ожидания/отказ от публикации результата; нельзя обещать отмену уже принятого провайдером запроса или возврат средств. Для V1 достаточно не принимать результат после отмены и завершать ожидание в пределах сетевого тайм-аута.

### 8.2. Контракты API

- `/api/state`: доступные профили, выбранный профиль, безопасные настройки и наличие ключей; профиль CV и его источник. Секреты не возвращаются.
- Новый endpoint списка моделей выбранного провайдера: работает только с разрешённым provider/profile, не принимает произвольный URL; не запускает генерацию.
- Endpoint проверки/сохранения/удаления ключа: использует выбранный provider, существующий `X-Token` и серверную блокировку при изменении credentials.
- `/api/analyze`: передаёт `cv_hash`, выбранный профиль и явные overrides, идентификатор снимка настроек и `paid_confirmed`. Сервер заново разрешает/проверяет конфигурацию, сравнивает идентификатор и CV, фиксирует snapshot до сети.
- Идентификатор snapshot вычисляется из нормализованных настроек без ключа. Согласие действительно только для этого snapshot и текущего CV; изменение модели сервером после выдачи идентификатора требует нового согласия.
- Идентификатор одного обращения анализа защищает от двойного клика: конкурентный запрос получает busy, повтор с тем же ID не создаёт вторую генерацию в текущем процессе. При неизвестном исходе не повторять его автоматически. Это не гарантия exactly-once после рестарта приложения.
- Ответ анализа: профиль плюс `cv_hash`, безопасные метаданные провайдера/модели/usage и предупреждение о сокращении входа. При ошибке — нормализованный код без ключа или сырого CV.

Обновить EN/TR тексты и README: убрать глобальное обещание «никогда не платит». В бесплатном режиме явно сохраняется бесплатная гарантия приложения; в платном — отдельное предупреждение о тарификации API и отдельном биллинге от чат-подписки.

## 9. CLI

Добавить выбор профиля/модели в терминальный сценарий и явные параметры, например:

```text
python apply.py --llm-profile free
python apply.py --llm-profile openai --llm-model <supported-model-id>
python apply.py --llm-profile claude --llm-model <supported-model-id> --allow-paid
```

- Без аргументов сохраняется безопасная миграция на бесплатный профиль.
- При выборе потенциально платного режима в интерактивном терминале показывать провайдера, точный ID, лимит токенов и вопрос согласия перед каждым анализом.
- В неинтерактивном режиме отсутствие `--allow-paid` запрещает платную генерацию; разрешение относится только к явно выбранной модели текущего вызова. Из конфигурации его не подставлять.
- `--allow-paid` не является разрешением реальных откликов и не меняет DRY_RUN.
- Валидный кэш можно использовать без генерации и оплаты. Для нового анализа другой моделью требуется явное действие/параметр повторного анализа; сохранённый кэш не выдавать за ответ вновь выбранной модели.

## 10. Ошибки, повторы и расходы

Нормализованные коды: `invalid_llm_config`, `missing_key`, `invalid_key`, `model_access_denied`, `unsupported_model`, `paid_consent_required`, `rate_limited`, `insufficient_quota`, `provider_unavailable`, `request_timeout`, `model_refusal`, `output_incomplete`, `invalid_profile`, `cv_changed`, `analysis_cancelled`.

- Не определять все коды только по HTTP-статусу: например, 429 может означать rate limit или отсутствие квоты; учитывать безопасно разобранный provider error code.
- В платном explicit-режиме V1 выполняет **одну генерацию на подтверждённое действие**. Автоматических повторов генерации при 429, 5xx, тайм-ауте, невалидном JSON или обрыве нет. Повтор — новое действие пользователя с новым согласием.
- Негенерационные GET-запросы можно повторять ограниченно: максимум один повтор при временной ошибке с ограниченной задержкой; не повторять неверный ключ/доступ.
- Бесплатный `free_auto` сохраняет ограниченные попытки других проверенно бесплатных моделей. Не зацикливаться при недоступности сервиса.
- Тайм-аут/закрытие GUI не доказывает отсутствие списания. Сообщать, что результат и стоимость запроса могут быть неизвестны.
- Usage показывается только при наличии в ответе; отсутствие счётчика не равно нулевому расходу. Денежную стоимость в V1 не вычислять по устаревшему локальному прайсу. Направлять к биллингу провайдера.

## 11. Хранение профиля и миграция

- Существующие ключ OpenRouter и настройки продолжают работать без ручного переноса.
- Если раздел `llm` отсутствует, выбран бесплатный профиль. Неправильный явно заданный раздел — ошибка, не молчаливый fallback.
- Добавить отдельные `llm_preferences` и `cv_profile_metadata` в настройки. Существующая схема самого `cv_profile` не расширяется служебными полями.
- Метаданные результата: provider, requested/returned model, версия схемы/prompt, дата анализа, digest анализируемого текста, признак сокращения и доступный usage. Не дублировать полный CV или ключ.
- Смена выбранной модели не стирает уже проверенный профиль, привязанный к тому же CV. Показывать его фактический источник и предлагать явный новый анализ; не выполнять оплату автоматически.
- Старый профиль без метаданных обозначается «источник неизвестен», не приписывается выбранной модели. Существующее правило недоверия к кэшу без совпадающего CV-хеша сохраняется.
- Успешный повторный анализ заменяет профиль/метаданные только после полной валидации, проверки CV и отсутствия отмены. Ошибка оставляет прежний соответствующий этому CV профиль доступным, явно показывая, что новый анализ не удался.
- Замена CV по-прежнему очищает старый профиль и метаданные, независимо от LLM-провайдера. GUI не восстанавливает старые значения из `S.profile`.

## 13. Проверки и критерии приёмки

### Unit / HTTP mocks

- Все приоритеты настроек, конфликты и неверные типы; незавершённый explicit-профиль не запускается.
- Бесплатность: платная цена, пропущенная цена, NaN/Infinity, ошибочный каталог, изменение цены между discovery и вызовом — генерация запрещена при `free_only`.
- Верные endpoint/headers/body для каждого провайдера; секреты не уходят на другой host и не пересылаются при redirect.
- Native model list не принимается за доказательство Structured Outputs; capabilities и выходной лимит проверяются отдельно.
- Адаптация схемы не меняет оригинал; локально продолжают отклоняться неправильные годы, массивы, длины, лишние поля и повторные JSON-ключи.
- Отказы, пустые/неожиданные content-блоки, обрыв, неправильный JSON, HTTP 401/403/429/5xx и тайм-ауты.
- Нет автоматического платного fallback/retry; один подтверждённый анализ — максимум одна генерация.
- Нельзя использовать старое согласие для другого CV, модели или токенного лимита.
- Двойное обращение с одним ID не создаёт два платных вызова; Stop/ошибка всегда снимают reservation/GUI-lock.
- Раздельные env/.env ключи, сохранение/удаление только выбранной записи, UTF-8, атомарная запись и безопасные права; отсутствие ключа в любых ошибках/ответах/логах.
- Кэш: тот же CV, новый CV, старые настройки, смена модели, неуспех повторного анализа и отмена; нет неверной атрибуции источника.

### GUI / CLI

- Переключение провайдера меняет модели и key status, но само не запускает генерацию.
- Платный режим без согласия блокируется на сервере, даже если обойти checkbox.
- После смены модели/CV или завершения обращения согласие сброшено.
- Устаревший snapshot/CV отклоняется до сети; действующий анализ неизменяем.
- После ошибок/отмены UI снова доступен; нет восстановления профиля от старого CV.
- Старый бесплатный сценарий и ручной ввод работают без ключей OpenAI/Anthropic.
- CLI без разрешения расходов не вызывает платную модель и не меняет DRY_RUN.
- Существующие тесты формы, истории, квот, UTF-8, привязки CV и конкуренции Start продолжают проходить.

### Выпуск

Обычные unit/browser/CI/selftest не используют реальные API-ключи и не выполняют платную генерацию. Транспорт тестируется моками, браузер — локальными маршрутами. Сетевые smoke-тесты помечены отдельно и не запускаются по умолчанию.

Если selftest продолжает обращаться к публичному каталогу OpenRouter, это явно отделяется от проверки конкретного выбранного провайдера и не требует native ключей. Сборка не должна объявлять «OpenAI/Claude проверены», если проверялся только OpenRouter.

## 14. Статус согласования и подготовка к реализации

Согласованы `.env`, Git-исключения и пустой `.env.example`, именованные профили, выходной лимит 4096, один платный генерационный запрос на действие, отдельное подтверждение каждого платного анализа и транспорт `urllib`.

При реализации остаётся проверить точные стартовые ID моделей OpenAI/Anthropic и capabilities по актуальной документации. Не выбирать самую дорогую модель по умолчанию и не приписывать пользователю выбор ID, который он не называл. Проверки выполнить без платной генерации; реальный smoke-test требует отдельного разрешения.

До реализации и тестирования рабочим режимом остаётся текущий OpenRouter free. Прямые платные подключения нельзя считать реализованными или протестированными.
